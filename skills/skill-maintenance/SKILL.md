# Skill maintenance

Compile reusable normative feedback into the narrowest existing authority
without turning policy into a transcript or calling an unpublished draft
retained.

## Admit durable feedback

Treat feedback as a policy candidate when at least one is true:

- the human owner explicitly asks for a lasting rule;
- the same correction recurs with one stable reusable lesson; or
- strongly emphasized feedback states an important future constraint.

Intensity raises priority, not scope. Do not mutate policy for a one-off task
instruction, personal fact, incident-only preference, or frustration whose
reusable meaning is unclear.

## Extract the rule

Write:

```text
Trigger:
Rule:
Scope:
Compliant move:
Exceptions or escalation:
```

Preserve force and boundary. Remove insults, emotional chronology, incident
history, dates, and self-justification. Put provenance in version history or a
private continuity record.

## Ratchet the owner

1. Search the current package or repository catalog and source to find the
   existing owner.
2. Amend that owner first and remove superseded, conflicting, or duplicate
   wording in the same change.
3. Keep always-loaded instructions for boundaries that must govern every
   matching action; use one coherent skill for triggerable procedure.
4. Create a new skill only when no coherent owner exists and the rule forms a
   reusable workflow with reliable triggers.
5. Use deterministic enforcement only when the rule is mechanically decidable;
   strong feedback alone does not justify a hook.

Edit authoritative source, never an installed projection or generated output.

## Validate the ratchet

Test at least one positive case where the durable trigger applies and one
negative control where similar language is episodic or out of scope. Check that
the positive case changes the correct owner and follows the compliant move, and
that the negative case does not manufacture policy.

Run the standard skill validator and the nearest existing catalog or behavior
fixture. Publish through the owner's normal path and confirm the consuming
catalog resolves to that published source before saying the feedback is
retained.
